# BotNastya

WhatsApp-бот шахматной школы: диалоги на русском/казахском, заявки в MoyKlass,
обращения управляющим, CRM-уведомления, посещаемость и follow-up.

## Локальная проверка

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python test_pre_deploy_smoke.py
.venv/bin/python -m unittest -v test_reliability test_conversation test_debt_notifications test_incidents test_branch_routing test_campaigns
```

Оба набора используют тестовые ключи и временные файлы состояния. Регрессионные
тесты подменяют сетевые вызовы; реальные сообщения не отправляются.

Заявка бота создаёт карточку ученика в выбранном филиале, комментарий с курсами
и задачу соответствующему управляющему. Автоматической записи в учебную группу
больше нет: прежний общий `LEAD_CLASS_ID=341820` указывал на архивную группу Аркады
и добавлял её филиал к чужим карточкам. Старые `LEAD_CLASS_ID`, `LEAD_STATUS_ID`
и `MANAGER_ID` из окружения больше не используются. Ответственный определяется
среди сотрудников выбранного филиала; при неоднозначности заявка сохраняется
в файл ошибок без назначения чужому менеджеру. Для существующей карточки
сохраняются прежние филиалы и добавляется выбранный. Уведомления используют
`mainFilialId`; несколько филиалов без основного не означают выбор первого.

Аркада и Камал предлагают шахматы, английский и математику. Пакетный прайс
из обновления 28.10.2026 внесён в базу знаний. Для двух детей — по 25 000 тг,
для трёх — по 20 000 за каждого в месяц за один курс. Пригласивший одного/двух
друзей платит 25 000 / 20 000 тг в месяц за курс; за трёх друзей получает месяц
в подарок. Совмещение скидок не обещается. Для продвинутых шахматных групп
скидки индивидуально рассчитывает администратор, базовые тарифы 35 000 / 40 000
сохранены. В BINOM эти акции не действуют, семейная скидка 10% сохранена отдельно.
Во всех BINOM и школе №59 — 24 000 тг за 3 занятия в неделю или 18 000 за 2.
Школа №59 предлагает английский и математику; для оформления нужны отдельный
активный филиал CRM «Школа номер 59» с назначенной Томирис. Бот находит его
автоматически при оформлении заявки; код менять и перезапускать процесс не нужно.
Опционально ID/контакт можно задать через `SCHOOL_59_FILIAL_ID`,
`SCHOOL_59_MANAGER_NAME`, `SCHOOL_59_MANAGER_PHONE`. По умолчанию — Томирис
Ержановна, +7 771 231 4549. До создания филиала бот не подтверждает запись,
даёт её контакт, а попытку сохраняет в файл ошибок.
Harmony, Harmony Global, NGS и Quantum направляются в администрацию школы
без создания заявки, callback и рекламного напоминания.

Существующие ошибочные привязки не исчезают после обновления кода. Для аудита
есть отдельный скрипт, который только читает CRM и сохраняет частный JSON
со снимками карточек и предложениями исправлений:

```sh
.venv/bin/python scripts/audit_branch_leads.py --env-file .env --output /tmp/branch-audit.json
```

Он исключает из предложений записи с занятиями, оплатами или неоднозначным
филиалом. Удаление исторических записей выполняется отдельно после проверки
плана; этот скрипт ничего не удаляет и не отправляет сообщений.

Для запуска заполните `.env` по `.env.example`, затем:

```sh
.venv/bin/python -m uvicorn bot:app --host 127.0.0.1 --port 8000
```

`GET /health` проверяет доступность процесса, без обращения к внешним API.
Адрес Green API задаётся через `GREEN_API_URL` (`apiUrl` из кабинета провайдера).
По умолчанию используется `https://api.greenapi.com`: прежний адрес
`api.green-api.com` может быть недоступен с сервера при работающем WhatsApp.
При таймаутах отправки проверьте доступность API, даже если `/health` отвечает `ok`.
Запускайте **один worker**: буферы диалогов, лимиты и защита от параллельных
дублей находятся в памяти процесса. История переписки, известные факты, передача управляющему и запреты контакта
сохраняются в `conversation_state.sqlite3` и переживают рестарт/таймаут.
Не удаляйте этот файл при обновлениях. Состояние CRM и посещаемости сохраняется атомарно.

При первом обращении бот подгружает до 60 последних сообщений этого чата через
Green API `getChatHistory` (если провайдер располагает историей). Последующие ответы
используют локальную память; сетевой сбой истории не останавливает обработку.
Несколько сообщений собираются за 8 секунд тишины (`BUFFER_DELAY`). Новое входящее
отменяет устаревший ответ, в том числе ожидающий лимита отправки. Перед отправкой
ответа бот дополнительно проверяет последние сообщения этого чата через Green API:
свежий текст с задержавшимся вебхуком возвращается в обработку, а устаревший ответ
отменяется. Поздний вебхук того же сообщения не вызывает повторного ответа.
Это дополнительная проверка: история у провайдера тоже может обновляться с задержкой;
её недоступность не останавливает обычную обработку входящих вебхуков.

Связь с учеником, досье и результат проверки CRM сохраняются в истории и переживают
перезапуск. По истечении пяти часов бот обновляет данные, сохраняя ранее установленную
связь при сбое CRM. Ошибка соединения/авторизации отличается от пустого поиска;
повторная проверка после сбоя — не чаще раза в минуту. Статус «Клиент» проверяется
отдельно от наличия карточки. Сбой расписания не отменяет совпадение по телефону.
Фразы «Наш ребёнок обучается у вас» / «Балам сізде оқиды» переключают разговор на
поддержку: возраст, подбор тарифа, новая заявка и рекламные напоминания не нужны.
Это заявление не привязывает номер к чужой карточке по имени. Контакт тренера бот
берёт из ближайших занятий подтверждённого по телефону ученика. Если получить его
нельзя, предлагает контакт управляющего известного филиала либо уточняет филиал.
Устаревшее расписание и баланс из старого досье не передаются модели как актуальные.

Ответ «10» на вопрос о возрасте сохраняется так же, как «10 лет».
«Для себя» не определяет возраст: бот уточняет его до выбора взрослого сценария.
Фразы «мне 13», «ребёнку 13», «Мен 13 жастамын» сохраняют возраст и без слова «лет».
До 18 лет действуют детские варианты: группы по уровню и индивидуальные занятия;
с 18 лет — индивидуальные. Например, при 3-м разряде детская группа стоит
35 000 тг/месяц (3 раза в неделю по 1,5 часа). Уточнённый возраст имеет приоритет
над прежним предположением бота; явный выбор индивидуальных сохраняется.

«Не пиши мне»/«не звоните»/«жазбаңыз» сохраняют постоянный запрет всех сообщений
этому контакту, включая CRM. Бот ничего не отвечает на отказ. Короткие благодарности
и подтверждения не запускают продажи. «Да» на предложение и новые вопросы обрабатываются.
Рабочие номера управляющих и получатели служебных employee-уведомлений исключены
из диалогов и follow-up; служебные уведомления сотрудникам продолжают работать.
Дополнительные номера задаются в `INTERNAL_PHONES` через запятую.
Если follow-up включён, допустимо только одно напоминание на контакт; факт отправки
сохраняется. Таймер тоже переживает перезапуск: два часа отсчитываются от успешной
доставки ответа провайдеру. Пока ответ не отправлен или ожидает повторной попытки,
напоминание не уходит. Загрузка старых диалогов без сохранённого таймера сама по себе
не запускает напоминания. Действующим ученикам, отказавшимся и закрытым заявкам его не отправляем.
Отказ самой школы (например, ребёнку 4,5 года), обращение о работе и «посоветуюсь и
отпишусь» также закрывают напоминания. Новые вопросы клиента продолжают обрабатываться.
«Отпишусь» **не является** отпиской; «отпишите меня» сохраняет запрет контакта.
Казахский сохраняется после коротких ответов, имени и названия филиала. Подтверждение
заявки, возрастной отказ и ряд других типовых ответов используют готовый текст RU/KZ.
Запросы других клубов не приводят к рекомендациям конкурентов.

Готовый ответ сохраняется до отправки. При отказе отправки бот повторяет попытку
с паузой, без повторного обращения к ИИ или CRM, до 24 часов. Новое сообщение клиента
или запрет контакта отменяет старый ответ. Очередь переживает перезапуск.
Это повторная попытка доставки, а не рекламное напоминание. При сетевом таймауте
невозможно гарантировать отсутствие дубля: провайдер мог принять сообщение до разрыва.

## Кампании из Excel

По умолчанию `CAMPAIGNS_ENABLED=0`: установка кода, создание черновика и импорт
контактов ничего не отправляют. Очередь управляется локально через CLI, публичного
HTTP-метода для запуска нет. Перед массовым запуском требуется проверить аудиторию
и способ подключения WhatsApp: паузы и лимиты не гарантируют отсутствие блокировок.
Прежнее входящее обращение не заменяет согласие на рекламные сообщения.
[WhatsApp Business Messaging Policy](https://business.whatsapp.com/policy/) требует
согласия и соблюдения отказов. Текущий транспорт — Green API `sendMessage`, не
реализация шаблонных кампаний WhatsApp Business Platform. Для официальной Business
Platform исходящие инициирующие сообщения требуют одобренных шаблонов; такой
транспорт подключается отдельно. Возможность рассылки должна соответствовать
договору и ограничениям используемого провайдера.

Форматы: `.xlsx` или CSV UTF-8, до 50 000 строк и 10 MiB. Первая строка —
заголовки `Телефон`, `Имя`, `Филиал`, `Согласие на рассылку`,
`Подтверждение согласия`. Обязателен только столбец телефона; однако в очередь
попадают лишь строки с `да` и непустым подтверждением (где/когда получено согласие).
Для остальных состояние `no_consent`. Отметка не проверяет достоверность согласия
автоматически: её подтверждает оператор по реальному источнику.
Если владелец явно подтвердил согласие всего списка, `import --consent-note
"Кто и когда подтвердил согласие для этого файла"` сохраняет это подтверждение
для строк без отметки согласия. Явные отказы в таблице и сохранённые отписки
оно не отменяет.
В XLSX используется лист `Контакты`, единственный лист или явно заданный `--sheet`.
Формулы не исполняются и отклоняются. Телефоны нормализуются, дубли исключаются;
неоднозначные номера не угадываются. При конфликте согласий номер исключается.
Импорт возможен только в черновик; текст и условия кампании после создания неизменны.
Повторный импорт не повышает неизвестное/отрицательное согласие до положительного:
для исправленной аудитории создайте новый черновик с новым ID.

```sh
venv/bin/python manage_campaigns.py create campaign_gm_intellect.json
venv/bin/python manage_campaigns.py import gm-intellect-2026-10 /private/path/contacts.xlsx
venv/bin/python manage_campaigns.py preview gm-intellect-2026-10
```

`campaign_gm_intellect.json` содержит согласованный текст: два направления —
55 000 тг/месяц, время диагностики согласует управляющий, отказ словом «СТОП».
По уточнению владельца от 28.10.2026 даты 29–31 октября убраны.
`expires_at: null` означает отправку до завершения очереди или остановки оператором;
для ограниченной по времени акции указывается ISO-дата с часовым поясом.
Для следующих акций нужен новый файл с собственным ID и условиями.

Для отправки оператор включает `CAMPAIGNS_ENABLED=1` в окружении службы,
перезапускает её, затем отдельно активирует проверенный черновик:

```sh
venv/bin/python manage_campaigns.py activate gm-intellect-2026-10
venv/bin/python manage_campaigns.py report gm-intellect-2026-10
venv/bin/python manage_campaigns.py set-limits gm-intellect-2026-10 --interval-sec 60 --hourly 60 --daily 0
venv/bin/python manage_campaigns.py pause gm-intellect-2026-10
venv/bin/python manage_campaigns.py cancel gm-intellect-2026-10
venv/bin/python manage_campaigns.py export gm-intellect-2026-10 /private/path/campaign-report.json
```

Одновременно активна одна кампания. Отправка только 09:00–20:00 Asia/Almaty.
Для GM Intellect по запросу владельца от 29.10.2026: интервал от 60 секунд,
максимум 60 попыток за скользящий час, без отдельного суточного лимита (`daily: 0`).
За полное окно 09:00–20:00 теоретически доступно 660 отправок; ожидание ответа,
транспорта и другие проверки могут уменьшить фактическое число. При отсутствии параметров
в новом описании кампании используются 10 минут, 6 в час и 30 в сутки.
Эти значения — ограничения нагрузки, а не «безопасный порог» WhatsApp.
Они сохраняются в SQLite между перезапусками и действуют совместно с общим
лимитом WhatsApp. Диалоги и служебные сообщения имеют приоритет: кампания
не стартует при ожидающих ответах и расходовании половины общей квоты.
Для этого режима общие `WA_MAX_PER_HOUR=120`, `WA_MAX_PER_DAY=0`,
`WA_WARMUP_MODE=0`: общего суточного потолка нет, половина часового бюджета
остаётся для диалогов. Ответы клиентам
могут уменьшить фактический объём рассылки. `set-limits` меняет только темп,
сохраняя историю попыток, отказы, текущий статус и израсходованные квоты.
Сотрудники и отписавшиеся исключаются, недавно активные чаты откладываются
на 24 часа после последнего входящего. Отменённая до HTTP отправка возвращается
в очередь без расходования квоты кампании; одному номеру
не отправляется новая кампания в течение 30 дней после попытки предыдущей.

Перед отправкой проверяется состояние аккаунта; после ожидания лимита повторно
проверяются пауза, срок, отказ и новые входящие. HTTP-ошибки, неопределённый
результат или ошибки статуса доставки ставят кампанию на паузу. `idMessage`
означает принятие провайдером, не подтверждённую доставку. Статусы `sent`,
`delivered`, `read` учитываются отдельно, если провайдер присылает
`outgoingMessageStatus`; без этих вебхуков доставка остаётся `unknown`.
События `stateInstanceChanged` и ограничения провайдера также останавливают очередь.
Статус `noAccount` исключает только конкретного получателя без WhatsApp, сохраняя
неуспешную попытку; остальные получатели продолжают обрабатываться.
Пауза не может отозвать уже принятый провайдером запрос.

Любой рестарт ставит активную кампанию на паузу, незавершённую попытку переводит
в `uncertain`. Автоматических повторов рекламных отправок нет. Перед ручным
продолжением оператор проверяет отчёт; `activate` продолжает только ещё не начатые
строки. Не удаляйте `campaigns.sqlite3`: в нём история, согласия, отказы, квоты,
точный текст и ответы. База и JSON-экспорт содержат контакты, храните их приватно.

Полученное предложение передаётся ИИ даже после очистки короткой истории.
«+» означает интерес, «Камал»/«Аркада» — выбор филиала, но не бронь места.
После окончания акции бот не обещает истёкшие даты/условия. Действующему ученику
не создаётся новая шахматная заявка; запрос по диагностике передаётся управляющему
выбранного филиала без изменения его текущего места обучения.
Явный отказ исключает будущие кампании; bare «нет» считается отказом только
на первый отклик, а последующие ответы «нет» остаются частью диалога.
Жалобы на спам, просьбы удалить номер, явный отказ и «СТОП» после рассылки
сохраняют общий запрет контакта, отменяют подготовленные ответы и follow-up.
Бот один раз отвечает: «Извините, что побеспокоили. Больше не будем присылать
вам рекламные сообщения.» Для казахского обращения используется казахский текст.
Это единственное исключение из запрета исходящих: резерв извинения сохраняется
в SQLite до отправки. При дубликате, рестарте или неопределённом результате
повторной попытки нет. Извинение не отправляется по старым входящим и после
ожидания более пяти минут. Отказы вне контекста кампании по-прежнему закрываются
без ответа. Обычные вопросы о цене, отсутствие опыта и отказ от одного курса
при интересе к другому не считаются жалобой на рассылку.
Явные формулировки распознаются до вызова ИИ. Для остальных реакций в контексте
кампании ИИ доступен `decline_campaign`: отказ имеет приоритет над одновременными
вызовами создания заявки или обращения к управляющему и использует то же
одноразовое извинение. В обычных диалогах этот инструмент не предлагается.
Рекламная отправка не запускает follow-up.

## Расходы и ежедневный отчёт

`usage_state.sqlite3` хранит фактический `usage` ответов API, кешированные токены,
выходные токены, секунды Whisper, оценку USD и события: входящие сообщения,
ответы, заявки, обращения управляющему, CRM/служебные сообщения и напоминания.
Учёт ведётся для обоих этапов вызова модели, включая результат, отменённый из-за
нового сообщения клиента. Неизвестный тариф, отсутствующий usage или ошибка API
помечаются как неизвестная стоимость, а не нулевой расход. Тариф сохраняется
в каждой записи, его изменение не пересчитывает прошлые дни.

По умолчанию отчёт отправляется на **+7 777 955 9999 каждый день в 09:00 Asia/Almaty**
за предыдущий календарный день. Содержит уникальных написавших клиентов, впервые
появившихся с начала учёта, выполненные действия, ошибки отправок, токены, расходы
по моделям/операциям и пять самых затратных чатов с маскированными номерами.
Номер получателя исключён из продаж. Отчёт строится без ИИ; отправленные дни
помнятся после рестарта. Пропущенные дни отправляются после восстановления работы,
неуспешная отправка повторяется. Первый день частичный; исторические расходы до
установки не восстанавливаются. Оценка не включает WhatsApp, сервер, CRM и налоги
и не заменяет счёт OpenAI (таймауты и внутренние повторы SDK могут скрыть usage).

Настройки: `DAILY_REPORT_ENABLED`, `DAILY_REPORT_PHONE`, `DAILY_REPORT_HOUR`,
`USAGE_STATE_FILE`, `OPENAI_PRICES_JSON` (см. `.env.example`). Для просмотра без отправки:

```sh
.venv/bin/python -c 'from datetime import date; from usage_reporting import UsageLedger; print(UsageLedger("usage_state.sqlite3").report_text(date(2026, 10, 7)))'
```

Экономичный default — `gpt-4.1-mini`, максимум 600 выходных токенов на вызов.
Существующий `OPENAI_MODEL` в `.env` имеет приоритет. Типовые ответы не вызывают ИИ,
а для контекста передаются до 30 последних сообщений с сохранением фактов и полных
групп вызовов функций. Тарифы проверены по официальным страницам
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini),
[GPT-4 Turbo](https://developers.openai.com/api/docs/models/gpt-4-turbo) и
[Whisper](https://developers.openai.com/api/docs/models/whisper-1).

Живая проверка модели, только по отдельному запуску (платные API-запросы,
WhatsApp и CRM подменены, используются вымышленные диалоги):

```sh
.venv/bin/python scripts/evaluate_dialogs.py --env-file .env --model gpt-4.1-mini
```

Уведомление «Занятие проведено в долг» требует свежего подтверждения CRM:
ученик посетил проведённый платный урок, списания за этот урок нет, а CRM показывает
неоплаченные занятия именно в его группе. Второе посещение месяца — только повод
для проверки. Поле API `paid` означает «платное занятие», а факт покрытия урока
проверяется через `bill` с `includeBills=true`.
При внесённой, но ещё не распределённой оплате, подходящем оплаченном абонементе,
бесплатном абонементе или неполных/недоступных данных уведомление не отправляется.
Эта проверка действует для монитора и клиентских вебхуков и повторяется после
ожидания очереди отправки. Долг по счёту за абонемент обрабатывается отдельными
платёжными уведомлениями; сам по себе он не доказывает занятие без покрытия.
В журнале `debt-check` сохраняется причина решения без ключей доступа.

## Деплой

```sh
bash deploy.sh
# При необходимости:
DEPLOY_HOST=botnastya DEPLOY_DIR=/home/almalinux/BotNastya bash deploy.sh
# При намеренной смене модели: сохраняет и восстанавливает .env при откате.
DEPLOY_OPENAI_MODEL=gpt-4.1-mini bash deploy.sh
```

Требуются SSH и право `sudo -n systemctl restart bot.service`. Скрипт проверяет
код в отдельном каталоге на Python сервера, сохраняет резервную копию,
обновляет код и проверяет службу и `/health`. При ошибке после замены файлов
восстанавливает предыдущий код. Рабочие файлы состояния не меняются; `.env` меняется
только при явном `DEPLOY_OPENAI_MODEL`, с резервной копией и откатом.
Версия записывается в `.deployed-revision`, копии — в `.deploy-backups/`.

`deploy_antiban.sh` предназначен для отдельной операции safe-start: он также
меняет режимы рассылок и лимиты. Для обычного обновления используйте `deploy.sh`.

Подтверждение `idMessage` означает принятие сообщения Green API; фактическая
доставка на телефон зависит от провайдера. Не включайте массовые уведомления
или дополнительные workers в рамках обычного обновления.
