# BotNastya

WhatsApp-бот шахматной школы: диалоги на русском/казахском, заявки в MoyKlass,
обращения управляющим, CRM-уведомления, посещаемость и follow-up.

## Локальная проверка

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python test_pre_deploy_smoke.py
.venv/bin/python -m unittest -v test_reliability test_conversation test_debt_notifications test_incidents
```

Оба набора используют тестовые ключи и временные файлы состояния. Регрессионные
тесты подменяют сетевые вызовы; реальные сообщения не отправляются.

Для запуска заполните `.env` по `.env.example`, затем:

```sh
.venv/bin/python -m uvicorn bot:app --host 127.0.0.1 --port 8000
```

`GET /health` проверяет доступность процесса, без обращения к внешним API.
Запускайте **один worker**: буферы диалогов, лимиты и защита от параллельных
дублей находятся в памяти процесса. История переписки, известные факты, передача управляющему и запреты контакта
сохраняются в `conversation_state.sqlite3` и переживают рестарт/таймаут.
Не удаляйте этот файл при обновлениях. Состояние CRM и посещаемости сохраняется атомарно.

При первом обращении бот подгружает до 60 последних сообщений этого чата через
Green API `getChatHistory` (если провайдер располагает историей). Последующие ответы
используют локальную память; сетевой сбой истории не останавливает обработку.
Несколько сообщений собираются за 8 секунд тишины (`BUFFER_DELAY`). Новое входящее
отменяет устаревший ответ, в том числе ожидающий лимита отправки. Перед отправкой
ответа бот дополнительно проверяет последние сообщения этого чата через Green API:
свежий текст с задержавшимся вебхуком возвращается в обработку, а устаревший ответ
отменяется. Поздний вебхук того же сообщения не вызывает повторного ответа.
Это дополнительная проверка: история у провайдера тоже может обновляться с задержкой;
её недоступность не останавливает обычную обработку входящих вебхуков.
Ответ «10» на вопрос о возрасте сохраняется так же, как «10 лет».

«Не пиши мне»/«не звоните»/«жазбаңыз» сохраняют постоянный запрет всех сообщений
этому контакту, включая CRM. Бот ничего не отвечает на отказ. Короткие благодарности
и подтверждения не запускают продажи. «Да» на предложение и новые вопросы обрабатываются.
Рабочие номера управляющих и получатели служебных employee-уведомлений исключены
из диалогов и follow-up; служебные уведомления сотрудникам продолжают работать.
Дополнительные номера задаются в `INTERNAL_PHONES` через запятую.
Если follow-up включён, допустимо только одно напоминание на контакт; факт отправки
сохраняется. Действующим ученикам, отказавшимся и закрытым заявкам его не отправляем.
Отказ самой школы (например, ребёнку 4,5 года), обращение о работе и «посоветуюсь и
отпишусь» также закрывают напоминания. Новые вопросы клиента продолжают обрабатываться.
«Отпишусь» **не является** отпиской; «отпишите меня» сохраняет запрет контакта.
Казахский сохраняется после коротких ответов, имени и названия филиала. Подтверждение
заявки, возрастной отказ и ряд других типовых ответов используют готовый текст RU/KZ.
Запросы других клубов не приводят к рекомендациям конкурентов.

Готовый ответ сохраняется до отправки. При отказе отправки бот повторяет попытку
с паузой, без повторного обращения к ИИ или CRM, до 24 часов. Новое сообщение клиента
или запрет контакта отменяет старый ответ. Очередь переживает перезапуск.
Это повторная попытка доставки, а не рекламное напоминание. При сетевом таймауте
невозможно гарантировать отсутствие дубля: провайдер мог принять сообщение до разрыва.

## Расходы и ежедневный отчёт

`usage_state.sqlite3` хранит фактический `usage` ответов API, кешированные токены,
выходные токены, секунды Whisper, оценку USD и события: входящие сообщения,
ответы, заявки, обращения управляющему, CRM/служебные сообщения и напоминания.
Учёт ведётся для обоих этапов вызова модели, включая результат, отменённый из-за
нового сообщения клиента. Неизвестный тариф, отсутствующий usage или ошибка API
помечаются как неизвестная стоимость, а не нулевой расход. Тариф сохраняется
в каждой записи, его изменение не пересчитывает прошлые дни.

По умолчанию отчёт отправляется на **+7 777 955 9999 каждый день в 09:00 Asia/Almaty**
за предыдущий календарный день. Содержит уникальных написавших клиентов, впервые
появившихся с начала учёта, выполненные действия, ошибки отправок, токены, расходы
по моделям/операциям и пять самых затратных чатов с маскированными номерами.
Номер получателя исключён из продаж. Отчёт строится без ИИ; отправленные дни
помнятся после рестарта. Пропущенные дни отправляются после восстановления работы,
неуспешная отправка повторяется. Первый день частичный; исторические расходы до
установки не восстанавливаются. Оценка не включает WhatsApp, сервер, CRM и налоги
и не заменяет счёт OpenAI (таймауты и внутренние повторы SDK могут скрыть usage).

Настройки: `DAILY_REPORT_ENABLED`, `DAILY_REPORT_PHONE`, `DAILY_REPORT_HOUR`,
`USAGE_STATE_FILE`, `OPENAI_PRICES_JSON` (см. `.env.example`). Для просмотра без отправки:

```sh
.venv/bin/python -c 'from datetime import date; from usage_reporting import UsageLedger; print(UsageLedger("usage_state.sqlite3").report_text(date(2026, 10, 7)))'
```

Экономичный default — `gpt-4.1-mini`, максимум 600 выходных токенов на вызов.
Существующий `OPENAI_MODEL` в `.env` имеет приоритет. Типовые ответы не вызывают ИИ,
а для контекста передаются до 30 последних сообщений с сохранением фактов и полных
групп вызовов функций. Тарифы проверены по официальным страницам
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini),
[GPT-4o mini](https://developers.openai.com/api/docs/models/gpt-4o-mini),
[GPT-4 Turbo](https://developers.openai.com/api/docs/models/gpt-4-turbo) и
[Whisper](https://developers.openai.com/api/docs/models/whisper-1).

Живая проверка модели, только по отдельному запуску (платные API-запросы,
WhatsApp и CRM подменены, используются вымышленные диалоги):

```sh
.venv/bin/python scripts/evaluate_dialogs.py --env-file .env --model gpt-4.1-mini
```

Уведомление «Занятие проведено в долг» требует свежего подтверждения CRM:
ученик посетил проведённый платный урок, списания за этот урок нет, а CRM показывает
неоплаченные занятия именно в его группе. Второе посещение месяца — только повод
для проверки. Поле API `paid` означает «платное занятие», а факт покрытия урока
проверяется через `bill` с `includeBills=true`.
При внесённой, но ещё не распределённой оплате, подходящем оплаченном абонементе,
бесплатном абонементе или неполных/недоступных данных уведомление не отправляется.
Эта проверка действует для монитора и клиентских вебхуков и повторяется после
ожидания очереди отправки. Долг по счёту за абонемент обрабатывается отдельными
платёжными уведомлениями; сам по себе он не доказывает занятие без покрытия.
В журнале `debt-check` сохраняется причина решения без ключей доступа.

## Деплой

```sh
bash deploy.sh
# При необходимости:
DEPLOY_HOST=botnastya DEPLOY_DIR=/home/almalinux/BotNastya bash deploy.sh
# При намеренной смене модели: сохраняет и восстанавливает .env при откате.
DEPLOY_OPENAI_MODEL=gpt-4.1-mini bash deploy.sh
```

Требуются SSH и право `sudo -n systemctl restart bot.service`. Скрипт проверяет
код в отдельном каталоге на Python сервера, сохраняет резервную копию,
обновляет код и проверяет службу и `/health`. При ошибке после замены файлов
восстанавливает предыдущий код. Рабочие файлы состояния не меняются; `.env` меняется
только при явном `DEPLOY_OPENAI_MODEL`, с резервной копией и откатом.
Версия записывается в `.deployed-revision`, копии — в `.deploy-backups/`.

`deploy_antiban.sh` предназначен для отдельной операции safe-start: он также
меняет режимы рассылок и лимиты. Для обычного обновления используйте `deploy.sh`.

Подтверждение `idMessage` означает принятие сообщения Green API; фактическая
доставка на телефон зависит от провайдера. Не включайте массовые уведомления
или дополнительные workers в рамках обычного обновления.
