# BotNastya

WhatsApp-бот шахматной школы: диалоги на русском/казахском, заявки в MoyKlass,
обращения управляющим, CRM-уведомления, посещаемость и follow-up.

## Локальная проверка

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python test_pre_deploy_smoke.py
.venv/bin/python -m unittest -v test_reliability test_conversation
```

Оба набора используют тестовые ключи и временные файлы состояния. Регрессионные
тесты подменяют сетевые вызовы; реальные сообщения не отправляются.

Для запуска заполните `.env` по `.env.example`, затем:

```sh
.venv/bin/python -m uvicorn bot:app --host 127.0.0.1 --port 8000
```

`GET /health` проверяет доступность процесса, без обращения к внешним API.
Запускайте **один worker**: буферы диалогов, лимиты и защита от параллельных
дублей находятся в памяти процесса. История переписки, известные факты, передача управляющему и запреты контакта
сохраняются в `conversation_state.sqlite3` и переживают рестарт/таймаут.
Не удаляйте этот файл при обновлениях. Состояние CRM и посещаемости сохраняется атомарно.

При первом обращении бот подгружает до 60 последних сообщений этого чата через
Green API `getChatHistory` (если провайдер располагает историей). Последующие ответы
используют локальную память; сетевой сбой истории не останавливает обработку.
Несколько сообщений собираются за 4 секунды тишины. Новое входящее отменяет
устаревший ответ, в том числе ожидающий лимита отправки.

«Не пиши мне»/«не звоните»/«жазбаңыз» сохраняют постоянный запрет всех сообщений
этому контакту, включая CRM. Бот ничего не отвечает на отказ. Короткие благодарности
и подтверждения не запускают продажи. «Да» на предложение и новые вопросы обрабатываются.
Рабочие номера управляющих и получатели служебных employee-уведомлений исключены
из диалогов и follow-up; служебные уведомления сотрудникам продолжают работать.
Дополнительные номера задаются в `INTERNAL_PHONES` через запятую.
Если follow-up включён, допустимо только одно напоминание на контакт; факт отправки
сохраняется. Действующим ученикам, отказавшимся и закрытым заявкам его не отправляем.

## Деплой

```sh
bash deploy.sh
# При необходимости:
DEPLOY_HOST=botnastya DEPLOY_DIR=/home/almalinux/BotNastya bash deploy.sh
```

Требуются SSH и право `sudo -n systemctl restart bot.service`. Скрипт проверяет
код в отдельном каталоге на Python сервера, сохраняет резервную копию,
обновляет код и проверяет службу и `/health`. При ошибке после замены файлов
восстанавливает предыдущий код. `.env` и рабочие файлы состояния не меняются.
Версия записывается в `.deployed-revision`, копии — в `.deploy-backups/`.

`deploy_antiban.sh` предназначен для отдельной операции safe-start: он также
меняет режимы рассылок и лимиты. Для обычного обновления используйте `deploy.sh`.

Подтверждение `idMessage` означает принятие сообщения Green API; фактическая
доставка на телефон зависит от провайдера. Не включайте массовые уведомления
или дополнительные workers в рамках обычного обновления.
