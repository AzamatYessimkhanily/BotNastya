## Что разработать

### 1. Новый эндпоинт `POST /moyklass-webhook/{secret}`

MoyKlass при срабатывании сценария отправляет `POST` с JSON-телом на этот URL.

**Защита:** MoyKlass не добавляет заголовки авторизации. Защита реализуется через секрет в URL-пути:
- Добавить в `.env` переменную `MOYKLASS_WEBHOOK_SECRET` (любая случайная строка, например UUID)
- Если `secret` в URL не совпадает с переменной — вернуть HTTP 404
- URL в MoyKlass настраивается как: `https://{сервер}/moyklass-webhook/{secret}`

**Структура входящего JSON от MoyKlass:**
```json
{
  "companyId": 27775,
  "event": "payment_new",
  "object": {
    "userId": 3284384,
    "summa": 30000,
    "date": "2026-06-15"
  },
  "time": 1781505281,
  "changedFields": [],
  "init": { "from": "CRM", "managerId": 98753 }
}
```

**Алгоритм обработки:**
1. Проверить секрет — если неверный, вернуть 404
2. Распарсить JSON, получить `event` и `object`
3. Найти телефон(ы) клиента (см. раздел 2)
4. Для каждого телефона определить язык сообщения (см. раздел 3)
5. Сформировать текст уведомления по шаблону (см. раздел 4)
6. Отправить WhatsApp через Green API (использовать существующую функцию `send_whatsapp`)
7. Сохранить уведомление в `chat_history` (см. раздел 5)
8. Вернуть `{"status": "ok"}` — всегда, даже при частичных ошибках (чтобы MoyKlass не делал повторные попытки)

---

### 2. Поиск телефона клиента

Стратегия зависит от типа события:

| Ситуация | Источник | API-запрос |
|---|---|---|
| В `object` есть поле `phone` (события `user_*`) | Прямо из объекта | — |
| В `object` есть `userId` | Запрос к API | `GET /users/{userId}` → поле `phone` |
| Только `lessonId`, нет `userId` (события `lesson_start_*`) | Список записанных учеников | `GET /lessonRecords?lessonId={id}&limit=200` → массив `userId` → телефон каждого |
| Только `classId`, нет `userId` (события `class_start_*`) | Список активных учеников группы | `GET /joins?classId={id}&statusId=2&limit=200` → массив `userId` → телефон каждого |

**Фолбэк для `/users/{userId}`:** если вернул 404, попробовать `GET /users?id={userId}` и взять `users[0].phone`.

**Нормализация телефона → chat_id (формат Green API):**
```python
clean = re.sub(r"[^\d]", "", phone)   # только цифры
if len(clean) == 10:
    clean = "7" + clean               # нет кода страны
elif len(clean) == 11 and clean[0] == "8":
    clean = "7" + clean[1:]           # KZ: 8→7
chat_id = f"{clean}@c.us"
```

### 3. Определение языка уведомления

Язык определяется автоматически **без вызова OpenAI** (экономия токенов):

1. Если `chat_history[chat_id]` существует — просмотреть последние 5 сообщений с `role: "user"`
2. Если хотя бы одно содержит казахские буквы (`ә і ң ғ қ ұ ү һ ө`) — отправить на **казахском**
3. В остальных случаях (нет истории, история на русском, история пустая) — отправить на **русском**

Шаблоны сообщений нужны на двух языках для каждого события.

**Известные события MoyKlass** (из официальной документации API):

| Код события | Описание | Поля в `object` |
|---|---|---|
| `payment_new` | Принят платёж | `userId`, `summa`, `date` |

| `sub_lessons_left` | В абонементе осталось мало занятий | `userId`, `visitCount`, `visitedCount` |
| `lesson_start_hours` | Занятие начнётся через N часов | `lessonId`, `date`, `beginTime` (**нет `userId`!**) |
| `lesson_start_days` | Занятие через N дней | `lessonId`, `date` (**нет `userId`!**) |
| `class_start_hours` | Старт группы сегодня | `classId` (**нет `userId`!**) |
| `class_start_days` | Старт группы через N дней | `classId`, `beginDate` (**нет `userId`!**) |
| `lesson_mark_set` | Выставлена оценка | `userId`, `type` (`home`/`lesson`), `value` |
| `join_new` | Создана новая запись в группу | `userId`, `classId`, `statusId` |
| `join_changed_state` | Изменился статус записи | `userId`, `classId`, `statusId` |

### 5. Критичный нюанс: AI должен знать об отправленном уведомлении

**Проблема:** бот отправляет автоматическое сообщение ("Оплата получена"), но оно не попадает в историю диалога. Когда клиент отвечает "Спасибо, а когда следующий платёж?" — AI не знает контекст и может вести себя некорректно (например, начать квалификацию как с новым лидом).

**Решение:** после каждой отправки автоуведомления — добавить его в `chat_history[chat_id]`.

```python
# Инициализировать историю если её нет
if chat_id not in chat_history:
    chat_history[chat_id] = [{"role": "system", "content": SYSTEM_PROMPT}]
    chat_history[chat_id].append({
        "role": "system",
        "content": (
            f"[ТЕЛЕФОН КЛИЕНТА]: {clean_phone}. Чат в WhatsApp — номер уже есть. "
            f"Для заявки в CRM используй этот номер."
        )
    })

# Системный контекст: объяснить AI что произошло
chat_history[chat_id].append({
    "role": "system",
    "content": (
        f"[АВТОУВЕДОМЛЕНИЕ CRM]: Клиенту автоматически отправлено системное сообщение: "
        f"\"{message}\". "
        f"Если клиент ответит — это ответ на данное уведомление. "
        f"Клиент является действующим учеником. "
        f"Отвечай как при работе с действующим клиентом (ТИП 9 в промпте). "
        f"НЕ создавай новый лид, НЕ спрашивай имя и телефон заново."
    )
})

# Само уведомление как сообщение ассистента
chat_history[chat_id].append({"role": "assistant", "content": message})
```

**Важно:** `last_activity[chat_id]` тоже обновить, чтобы сессия не протухла раньше времени.

## Тестирование (обязательно перед слиянием в `main`)

Разработчик обязан предоставить:

### Шаг 1 — Unit-тест шаблонов

Функция формирования сообщения должна возвращать корректный текст для каждого события. Написать простой тест (pytest или скрипт):

```python
assert "payment_new" шаблон содержит нужный текст

assert неизвестное событие возвращает None
# ... для каждого события
```

### Шаг 2 — Интеграционный тест: curl → бот → WhatsApp

После деплоя ветки на VPS — симулировать каждый вебхук через curl:

```bash
SECRET="значение из .env"
SERVER="https://ваш-сервер.ru"
TEST_USER_ID=3284384   # реальный userId из MoyKlass

# Тест 1: Платёж
curl -X POST "$SERVER/moyklass-webhook/$SECRET" \
  -H "Content-Type: application/json" \
  -d "{\"event\":\"payment_new\",\"object\":{\"userId\":$TEST_USER_ID,\"summa\":30000,\"date\":\"2026-06-16\"}}"

# Тест 2: Окончание абонемента
curl -X POST "$SERVER/moyklass-webhook/$SECRET" \
  -H "Content-Type: application/json" \
  -d "{\"event\":\"sub_end_days\",\"object\":{\"userId\":$TEST_USER_ID,\"endDate\":\"2026-07-01\"}}"

# Тест 3: Оценка за домашнее задание
curl -X POST "$SERVER/moyklass-webhook/$SECRET" \
  -H "Content-Type: application/json" \
  -d "{\"event\":\"lesson_mark_set\",\"object\":{\"userId\":$TEST_USER_ID,\"type\":\"home\",\"value\":5}}"

# ... аналогично для каждого события
```

Для каждого теста: WhatsApp-сообщение должно прийти на телефон тестового пользователя в течение 5 секунд.

### Шаг 3 — Тест ответа клиента на уведомление

1. Отправить тестовое уведомление (например, `payment_new`)
2. Ответить на него с тестового номера: "Спасибо, а когда следующий платёж?"
3. AI должен ответить как с действующим клиентом (ТИП 9) — не начинать квалификацию заново, не спрашивать имя/возраст

### Шаг 4 — Проверить неизвестное событие

```bash
curl -X POST "$SERVER/moyklass-webhook/$SECRET" \
  -H "Content-Type: application/json" \
  -d '{"event":"unknown_event","object":{"userId":3284384}}'
```

Ожидаемый результат: вернуть `{"status": "ok"}`, никакого сообщения не отправлять, в логах — строка `event=unknown_event: нет шаблона, пропускаем`.

## Что НЕ трогать

| Что | Почему |
|---|---|
| `SYSTEM_PROMPT` / `_SYSTEM_PROMPT_TEMPLATE` | Любое изменение ломает поведение бота |
| `POST /webhook` (Green API входящие) | Основной эндпоинт приёма сообщений |
| `process_dialog()` | Логика AI-диалога |
| `create_lead()` | Логика создания лидов в CRM |
| Существующие константы и переменные окружения | Только добавлять новые |
| Данные в `.env` | Только дописывать `MOYKLASS_WEBHOOK_SECRET` |

## Схема потока данных

```
MoyKlass CRM
  → [сценарий срабатывает по событию]
  → [действие "Отправить вебхук"]
  → POST /moyklass-webhook/{secret}
      │
      ├─ Проверка секрета (404 если неверный)
      ├─ Определение типа события
      ├─ Поиск телефона клиента (MoyKlass API)
      ├─ Определение языка (из chat_history)
      ├─ Формирование текста по шаблону
      ├─ send_whatsapp(chat_id, message)  ← Green API
      └─ Запись в chat_history (контекст для AI)

Клиент отвечает на уведомление в WhatsApp
  → POST /webhook (существующий эндпоинт)
  → process_dialog()  ← AI видит контекст автоуведомления
  → Ответ как с действующим учеником (ТИП 9)
```
